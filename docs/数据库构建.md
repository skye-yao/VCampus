# 数据库构建

本文说明 VCampus 数据库的两种建法：**从头构建**（全新机器 / 全新库）和**补充构建**（已经在跑的库，
只补缺失的部分）。测试库与演示数据的灌法与注意事项也在最后。

所有 SQL 文件都在 `VCampusServer/src/resources/` 下。**服务端没有任何自动迁移运行器**——`dist/` 只打包
jar、`lib/` 和启动脚本，不含 SQL；这些文件必须由人按顺序手工执行。

`migrations/README.md` 里那句话的含义就是这个顺序：**先有基础库（`init.sql`），再从 `001` 开始补课程模块。**

## 1. 前置条件

- **MySQL 8.0**。用到 `CHECK` 约束、生成列（`enrollment.active_course_id`）、
  `information_schema` 列探测与 `PREPARE`/`EXECUTE`，5.7 跑不动。
- **客户端字符集必须是 utf8mb4**。Windows 下 `mysql` 客户端默认不是 utf8mb4，而
  `init.sql` 里有 `gender VARCHAR(10) DEFAULT '男'` 这种中文默认值，用默认字符集导入会直接失败：

  ```
  ERROR 1067 (42000) at line 6: Invalid default value for 'gender'
  ```

  因此下面所有命令都显式带 `--default-character-set=utf8mb4`。
- **时区**。服务端 `DBUtil` 每个连接都执行 `SET time_zone = '+00:00'`，课程模块的时间列
  （`course_occurrence.start_at/end_at` 等）按 **UTC 墙钟**读写。手工写 SQL 校验数据时也要按 UTC 理解，
  例如 `seed/seed-course-demo.sql` 里 `2026-09-08 00:00:00` 对应北京时间 08:00。
- **连接配置**在 `VCampusServer/src/resources/db.properties`（键：`db.driver` / `db.url` /
  `db.username` / `db.password`）。测试库需要单独一份副本，用 `-TestConfigPath` 传给测试入口（见 §4）。

## 2. 从头构建

### 2.1 一次性命令序列

```bash
R=VCampusServer/src/resources

# 1) 核心库。init.sql 自带 CREATE DATABASE IF NOT EXISTS `virtual_campus` 与 USE，直接灌即可。
mysql --default-character-set=utf8mb4 -uroot -p < $R/init.sql

# 2) 学籍批量导入回执表（学籍批量导入依赖，缺了会报错）
mysql --default-character-set=utf8mb4 -uroot -p virtual_campus < $R/migrations/v101_student_information_batch.sql

# 3) 课程模块迁移，必须按编号顺序（大写 V0NN 会被这个通配符按序展开）
for f in $R/migrations/V00*.sql; do
  mysql --default-character-set=utf8mb4 -uroot -p virtual_campus < "$f"
done

# 4) AI 助手模块
mysql --default-character-set=utf8mb4 -uroot -p virtual_campus < $R/migrations/v201_ai_tables.sql

# 5) 图书馆演示数据。⚠️ init.sql 已经灌了 8 本书，所以必须先清空图书馆相关表，
#    否则会被它自己的空库守卫拒绝（见 §2.2）。只要库里还没有真正的借阅记录就可以清。
mysql --default-character-set=utf8mb4 -uroot -p virtual_campus -e "
SET FOREIGN_KEY_CHECKS=0;
DELETE FROM \`tblFineRecord\`;  DELETE FROM \`tblLossRecord\`;   DELETE FROM \`tblBookReview\`;
DELETE FROM \`tblReservation\`; DELETE FROM \`tblBorrowRecord\`; DELETE FROM \`tblBook\`;
SET FOREIGN_KEY_CHECKS=1;"
mysql --default-character-set=utf8mb4 -uroot -p virtual_campus < $R/sample_library_data.sql

# 6) 课程模块演示数据（人工演示用；想自己造数据就跳过）
mysql --default-character-set=utf8mb4 -uroot -p virtual_campus < $R/seed/seed-course-demo.sql
```

**不要灌 `seed-course-test.sql`。** 那是自动化测试的夹具，账号是合成账号，灌进演示库/真实库
只会污染数据（合成账号、`major` 被塞成英文名、`course_occurrence` 只有 4 条）。

`-p` 后面不跟密码，回车后交互输入。要在脚本里免交互，用 `MYSQL_PWD` 环境变量，**不要**把密码写进命令行
（会进 shell 历史与进程列表）：

```bash
export MYSQL_PWD='<密码>'
mysql --default-character-set=utf8mb4 -uroot virtual_campus < "$f"
unset MYSQL_PWD
```

按上面 6 步灌完（第 5、6 步都做）的期望结果：

| 指标 | 期望值 |
| --- | --- |
| 表总数 | 80 |
| `tbl_user` | 16（`init.sql` 15 + 演示数据新增的 `teacher02`） |
| `course` / `course_offering` | 12 / 16 |
| `course_occurrence` / `resource_booking` | 260 / 520 |
| `enrollment` | 41 |

### 2.2 顺序为什么是这样

- `init.sql` → `migrations/`：课程模块的表都带 `FOREIGN KEY` 指向 `tbl_user`、`major`、
  `course` 这些核心表，核心表必须先存在。
- `v101` 与 `v201` 互相独立，不依赖课程模块，放在 `V0NN` 前后都行。
- **`sample_library_data.sql` 必须在清空图书馆相关表之后**：它开头会检查 `tblBook`/`tblBorrowRecord`
  等表是否已有数据，非空就 `SIGNAL SQLSTATE '45000'` 拒绝执行。`init.sql` 自己就会灌 8 本书，
  所以"刚建好的库"对它来说**并不算空**——必须先清（§2.1 第 5 步）。这是防重复导入，不是 bug。
- `seed/seed-course-demo.sql` 放在所有迁移之后即可（见 §5，它对新旧两种顺序都做了兼容）。

### 2.3 装到非默认库里

`init.sql`、`migrations/v201_ai_tables.sql`、`sample_library_data.sql` 里都写死了
`CREATE DATABASE IF NOT EXISTS \`virtual_campus\`` / `USE \`virtual_campus\``。
**想装到别的库名（例如 `virtual_campus_course_test`），必须先把这几行改掉再灌**，否则会把表建到
`virtual_campus` 里去。例如：

```bash
R=VCampusServer/src/resources
mkdir -p /tmp/vc_test
for f in init.sql migrations/v201_ai_tables.sql sample_library_data.sql; do
  sed 's/`virtual_campus`/`virtual_campus_course_test`/g' "$R/$f" \
      > "/tmp/vc_test/$(basename "$f")"
done
mysql --default-character-set=utf8mb4 -uroot -p < /tmp/vc_test/init.sql
```

`migrations/V001…V007` 和 `v101` 里没有 `USE`，直接带库名灌即可。

## 3. 补充构建（已有库）

迁移文件是**手工按序执行**的 SQL，没有版本记录表。已经跑过的库只需要补缺的部分：

```bash
R=VCampusServer/src/resources

# 只补某一版（先确认这一版确实没跑过）
mysql --default-character-set=utf8mb4 -uroot -p virtual_campus < $R/migrations/V007_teacher_gradebook.sql

# 或者把全部编号灌一遍——注意 V003/V004 的 ALTER 段不可重复执行，见下
```

判断某一版是否已应用的实用办法是看 `information_schema`。**必须查这一版自己新增的对象**：
拿老版本就有的列去判断，会把"没跑过"误判成"跑过了"（例如 `grade.is_published` 是 `V001` 建的，
用它可以判断 `V001`，但绝不能拿来判断 `V007`）：

```sql
-- V007 的列在不在？submission_kind 只有 V007 会加（V004 建 grade_submission 时没有这一列）
SELECT COUNT(*) FROM information_schema.COLUMNS
 WHERE TABLE_SCHEMA = DATABASE()
   AND TABLE_NAME = 'grade_submission' AND COLUMN_NAME = 'submission_kind';

-- 某个迁移建的表在不在？
SELECT COUNT(*) FROM information_schema.TABLES
 WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'course_schedule_arrangement';
```

**可重复性一览：**

- `V001`、`V002`、`V005`、`V006`、`V007`：建表都是 `CREATE TABLE IF NOT EXISTS`，`V005`/`V007` 的
  `ALTER` 也先探测 `information_schema` 再决定跑不跑，整份文件可以重复执行。
- `V003`、`V004`：**建表段可重复，`ALTER` 段不能**。它们是给"已经存在、但还没有这些列"的表加列的
  （`ADD COLUMN status`、`DROP CHECK chk_course_offering_enrolled_count`、把
  `course_schedule_rule.arrangement_id` 收成 `NOT NULL` 等），再跑一次会报
  `Duplicate column name` / `Duplicate key name` / `Can't DROP ... check that does not exist`。
  这两份只应在缺列的空库上执行一次；已经跑过就跳过。
- `init.sql`、`migrations/v101_*.sql`、`migrations/v201_*.sql`：全部幂等，重复执行不会新增
  重复行（插入走主键 + `ON DUPLICATE KEY UPDATE` / `INSERT IGNORE`）。
- `seed/seed-course-demo.sql`、`seed-course-test.sql`：幂等，见 §5。
- `sample_library_data.sql`：**不可重复**，见 §2.2。

## 4. 测试库

课程模块的 MySQL / TCP 测试跑在名为 **`virtual_campus_course_test`** 的库上。这名字是硬约束：多个测试类
（如 `CourseModuleContentionInvariantTest`、`CourseQueryMySqlTest`）开头就断言
`DATABASE() = 'virtual_campus_course_test'`，不匹配直接拒绝运行——这是防止测试把真实库洗掉的保护，
不要绕过。

构建测试库（库名替换见 §2.3）：

```bash
R=VCampusServer/src/resources
DB=virtual_campus_course_test

sed "s/\`virtual_campus\`/\`$DB\`/g" $R/init.sql > /tmp/vc_test/init.sql
mysql --default-character-set=utf8mb4 -uroot -p < /tmp/vc_test/init.sql
mysql --default-character-set=utf8mb4 -uroot -p $DB < $R/migrations/v101_student_information_batch.sql
for f in $R/migrations/V00*.sql; do
  mysql --default-character-set=utf8mb4 -uroot -p $DB < "$f"
done
mysql --default-character-set=utf8mb4 -uroot -p $DB < $R/seed-course-test.sql
```

测试通过 `-TestConfigPath` 指向一份把 `db.url` 改成测试库的 `db.properties`。**这份文件必须放在一个
`resources/` 目录里**，例如 `<你的目录>/resources/db.properties`：

```bash
mkdir -p /tmp/vc_test/resources
sed 's#/virtual_campus?#/virtual_campus_course_test?#' \
    VCampusServer/src/resources/db.properties > /tmp/vc_test/resources/db.properties

pwsh -File scripts/test-teacher.ps1 -Suite Foundation -WithMySql -WithTcp \
     -TestConfigPath /tmp/vc_test/resources/db.properties
```

> **为什么必须带 `resources/` 这一层。** 服务端代码（`util/DBUtil`）不读 `--config=`，它固定从
> classpath 取 `resources/db.properties`。运行脚本把 `-TestConfigPath` 的**上上级目录**作为 classpath
> 条目插在 `VCampusServer/src` 前面，于是只有 `<dir>/resources/db.properties` 能盖住真实库那份配置。
> 把文件直接放成 `/tmp/test-db.properties`（上上级目录成了仓库根）时，classpath 里根本找不到
> `resources/db.properties`，DBUtil 会回落到 `VCampusServer/src/resources/db.properties` —— 于是
> **TCP 用例的进程内服务器连的是真实库，而夹具灌在测试库里**，表现为登录成功但数据对不上
> （例如 `teacher A must see exactly two terms but saw 1`）。这不是 seed 的问题，配置放对就绿。

> 多数迁移测试会**自己重建**受保护测试架构（抽 `init.sql` 里的 `tbl_user` DDL、依次灌 V001-V003、
> `seed-course-test.sql`、V004），所以手工建测试库主要用于跑服务层与 TCP 端到端用例。
> 两种顺序都必须能跑通，见 §5。

## 5. 课程模块数据文件

两份文件都幂等、都只动自己声明的 ID 区间，但用途不同，**不要混用**：

| 文件 | 用途 | 账号 |
| --- | --- | --- |
| `seed-course-test.sql` | 自动化测试夹具。`VCampusServer/test/` 下的迁移测试、服务层 MySQL 测试和 TCP 端到端测试按路径加载它 | `student-alpha` / `student-beta` / `teacher-alpha` / `teacher-beta` / `admin-alpha`，口令 `course-test-only`，盐 `Y291cnNlLXRlc3Qtc2FsdC12MQ==` |
| `seed/seed-course-demo.sql` | 人工演示数据。灌进演示库让课程模块有内容可看 | 与 `init.sql` 的 `tbl_user` 对齐，见 §5.1 |

> 两份文件的 ID 区间**有重叠**（major 10、course 1001/1002、offering 2001-2004、plan 4001、
> calendar 3001、occurrence 4201-4204……）。不要把它们灌进同一个库——测试夹具的合成账号和演示数据的
> 真实账号会争抢同一批 fixture 行。**测试库用 `seed-course-test.sql`，演示库用
> `seed/seed-course-demo.sql`。**
> 改测试夹具等于改测试基线，动之前先确认所有套件仍然通过（并且要同步改测试里写死的路径）；改演示数据则不受这个约束。

### 5.1 演示数据的账号与 `init.sql` 对齐

`seed/seed-course-demo.sql` 插入的 10 个账号（UID、姓名、学院、专业、`salt`、`password`）与 `init.sql`
的 `tbl_user` **逐列一致**：

| UID | 姓名 | 角色 |
| --- | --- | --- |
| `213242789` `213242790` `213242791` `213242793` `223242801` `223242802` `233242815` | 张三 / 李雨桐 / 王浩然 / 周可欣 / 孙婉清 / 吴承宇 / 郑晓彤 | 2 学生 |
| `teacher01` / `teacher02` | 李老师 / 王建国 | 1 教师 |
| `admin3` | 管理员3 | 0 管理员 |

盐为 `dGVzdHNhbHQxMjM0NTY=`，明文密码 `123456`。插入语句用
`ON DUPLICATE KEY UPDATE \`name\` = VALUES(\`name\`)`——**冲突时只刷新姓名，不动密码**，所以往真实库里
重灌不会改掉任何人的登录凭据。

`teacher02` 是这份文件相对 `init.sql` 额外引入的教师（`init.sql` 只有一位教师），它没有 `tblTeacher`
人事档案行；课程模块不需要，人事页面查不到属预期。

演示数据本身的名称（课程名、教室名、教学日历与排课方案名、通知标题）都是中文，与 `init.sql` 的中文学院/专业
保持一致；**测试夹具里那些 `Test Room 101`、`Course test calendar` 之类不会出现在演示库里**。

### 5.2 幂等与装载顺序

两份文件开头都探测 `course_schedule_rule.arrangement_id` 是否存在（V004 才加这一列），因此
**新旧两种装载顺序都支持**：

- 旧顺序（迁移测试常用）：`V001 → V002 → V003 → seed → V004`，此时还没有 `arrangement_id` 列；
- 新顺序（全新安装 / 演示库）：`V001 → … → V007 → seed`，此时列已存在。

清理是"先子后父"的定点删除，只删各自声明的固定 ID 区间。**任何区间之外的数据都不会被删改**，所以
往已经有人在用的演示库里重灌是安全的（只会重置课程模块那批 fixture）。

### 5.3 `seed/seed-course-demo.sql` 的数据规模

7 个专业（10-16，专业名与 `init.sql` 里学生的专业一致）、12 门课（1001-1012）、
16 个教学班（2001-2004、2010-2020、2024）、20 条排课规则（第 1-16 周）、**260 条 `course_occurrence`**、
4 间教室、41 条选课记录、15 条成绩、6 条选课计划项、4 条候补、7 份学籍、2 份培养方案
（计算机 / 信息工程各一份）、6 条课程通知、3 条事件 outbox。

每个有学籍的学生 `student_academic_profile.cohort_year` 都不一样，用来看"不同年级看到不同课程"：
`213242789`/`213242790`/`213242791`/`213242793` 是 2026 级（第 1 学年）、`223242801`/`223242802`
是 2025 级（第 2 学年）、`233242815` 是 2024 级（第 3 学年）。目录可见性规则要求
`course_year.year = course_offering.academic_year - cohort_year + 1`，所以这几个学生在 `2026/2`
学期各自看到的是不同年级的课。

`course_occurrence.start_at/end_at` 存 UTC；日历是 `Asia/Shanghai`，所以由"本地日期 + 节次起止时间"
减去 8 小时生成，例如第 1 周周二 1-2 节是 `2026-09-08 00:00:00` UTC（北京时间 08:00）。

## 6. 建完自检

```sql
USE virtual_campus;

-- 表数量（核心 39 + AI + 课程模块 + 学籍回执，全部灌完是 80）
SELECT COUNT(*) FROM information_schema.TABLES
 WHERE TABLE_SCHEMA = DATABASE() AND TABLE_TYPE = 'BASE TABLE';

-- 课程模块关键表都在
SELECT TABLE_NAME FROM information_schema.TABLES
 WHERE TABLE_SCHEMA = DATABASE()
   AND TABLE_NAME IN ('course', 'course_offering', 'course_occurrence',
                      'course_schedule_rule', 'course_schedule_arrangement',
                      'enrollment', 'grade', 'course_selection_window');

-- 灌了 seed 的话：occurrence 条数应与 rule_week 条数一致，预订数是实例数的两倍
SELECT (SELECT COUNT(*) FROM course_occurrence) AS occurrences,
       (SELECT COUNT(*) FROM course_schedule_rule_week) AS rule_weeks,
       (SELECT COUNT(*) FROM resource_booking) AS bookings;

-- 教学班的已选人数应与有效选课数一致（应为 0 行）
SELECT o.offering_id, o.enrolled_count,
       (SELECT COUNT(*) FROM enrollment e
         WHERE e.offering_id = o.offering_id AND e.status = 2) AS actual
  FROM course_offering o
 HAVING o.enrolled_count <> actual;

-- 有排课规则却没有实例的（应为 0）
SELECT COUNT(*) FROM course_schedule_rule r
 WHERE NOT EXISTS (SELECT 1 FROM course_occurrence o WHERE o.rule_id = r.id);

-- 演示库里不该有测试夹具的影子（这几项都应为 0）
SELECT (SELECT COUNT(*) FROM tbl_user WHERE UID LIKE '%-alpha') AS synthetic_accounts,
       (SELECT COUNT(*) FROM classroom WHERE `name` LIKE 'Test Room%') AS test_rooms,
       (SELECT COUNT(*) FROM teaching_calendar WHERE `name` LIKE 'Course test%') AS test_calendars;
```

## 7. 常见报错

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `ERROR 1067 Invalid default value for 'gender'` | 客户端字符集不是 utf8mb4 | 命令加 `--default-character-set=utf8mb4` |
| `ERROR 1049 Unknown database 'virtual_campus'` | 直接指定库名但库还没建 | 先灌 `init.sql`（它自己建库），或先 `CREATE DATABASE` |
| 表被建到了 `virtual_campus` 而不是你想要的库 | `init.sql` / `v201_ai_tables.sql` / `sample_library_data.sql` 里写死了 `CREATE DATABASE`/`USE` | 先 `sed` 改库名再灌，见 §2.3 |
| `ERROR 1644 Library is not empty; sample import refused` | `init.sql` 已经灌了 8 本书，图书馆不算空 | 先清空图书馆相关表再灌，见 §2.1 第 5 步；重复执行 `sample_library_data.sql` 也会报这个 |
| `Duplicate column name` / `Duplicate key name` | 重复执行了 `V003`/`V004` 的 `ALTER` 段 | 跳过已应用过的迁移，改灌缺失的版本，见 §3 |
| 测试报 `Refusing ... outside virtual_campus_course_test` | `db.properties` 指向了真实库 | 用 `-TestConfigPath` 指向测试库配置，不要改守卫 |
| TCP 用例登录成功但断言数据对不上（如 `teacher A must see exactly two terms but saw 1`） | `-TestConfigPath` 的文件没有放在 `resources/` 目录里，进程内服务器回落到真实库 | 放到 `<dir>/resources/db.properties`，见 §4 |
| 时间比预期差 8 小时 | 课程模块时间列是 UTC 墙钟 | 按 UTC 理解，或在查询里 `CONVERT_TZ` |
