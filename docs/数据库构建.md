# 数据库构建

## Windows 一键执行（MySQL 8 + Python 3）

在项目根目录双击 `setup-database.bat`，或者在 PowerShell 运行：

```powershell
python scripts/setup-database.py --demo
```

连接信息读取 `VCampusServer/src/resources/db.properties`；`mysql`、`mysqldump`、`python` 需要在 PATH 中。
脚本在修改已有数据库前将完整备份保存到 `.codex-tmp/database-backups/`。
首次建库执行 `init.sql`，已有基础库保留原数据；随后按文件名顺序执行 V001–V007、v101、v201。
`--demo` 只在课程表为空时导入课程演示数据；已有课程数据会拒绝导入，以免覆盖。
不需要演示数据时去掉 `--demo`。

`_vcampus_sql_history` 记录执行成功的文件及 SHA-256；重复运行自动跳过，已执行文件被修改时停止。
已有课程表却没有迁移记录的库需要先人工核对版本，脚本不会猜测并重跑 ALTER。
执行失败立即停止；MySQL DDL 不支持整批回滚，部分结构可能已提交，应结合备份检查后再继续。
此入口处理新库或已有完整基础表的库；不能自动修复任意旧版基础表。

> 现状说明：仓库里当前没有 `scripts/setup-database.py`，双击 `setup-database.bat` 只会提示找不到文件（本库也没有 `_vcampus_sql_history` 表，说明一直没用过这个入口）。上面的流程是按设计意图写的，实际建库请按下一节的顺序手工执行：`init.sql` → 迁移 → 种子；需要的话我可以把这个脚本补回仓库。

## 手工清库重建（推荐顺序）

删库之前先用 mysqldump 备份一份（`build-check/db-backup/` 下已有重建前的完整快照）。然后在 MySQL Workbench 或命令行按下面顺序执行，14 个文件全部成功后再启动服务端：

```sql
-- 1) 基础库：建表 + 基础数据 + 商店与银行演示记录
source VCampusServer/src/resources/init.sql;
-- 2) 迁移，严格按顺序
source VCampusServer/src/resources/migrations/V001_create_course_tables.sql;
source VCampusServer/src/resources/migrations/V002_create_schedule_tables.sql;
source VCampusServer/src/resources/migrations/V003_extend_course_management.sql;
source VCampusServer/src/resources/migrations/V004_admin_course_management.sql;
source VCampusServer/src/resources/migrations/V005_teacher_course_foundation.sql;
source VCampusServer/src/resources/migrations/V006_teacher_adjustment_requests.sql;
source VCampusServer/src/resources/migrations/V007_teacher_gradebook.sql;
source VCampusServer/src/resources/migrations/v101_student_information_batch.sql;
source VCampusServer/src/resources/migrations/v201_ai_tables.sql;
source VCampusServer/src/resources/migrations/v301_chat.sql;
source VCampusServer/src/resources/migrations/v301_shop_review_and_food_category.sql;
-- 3) 演示数据
source VCampusServer/src/resources/seed/seed-course-demo.sql;
source VCampusServer/src/resources/seed/seed-product-images.sql;
```

需要管理员权限时补一句（`init.sql` 故意把主管理员设成只读，其它管理员默认没有任何权限）：

```sql
INSERT INTO tbl_admin_permission (uid, academic_perm, library_perm, course_perm, shop_perm, bank_perm, user_perm)
VALUES ('admin',0,0,0,1,1,0), ('admin1',0,0,0,1,1,0)
ON DUPLICATE KEY UPDATE shop_perm=VALUES(shop_perm), bank_perm=VALUES(bank_perm);
```

重建后图书表只有 8 个题名，服务端第一次打开图书馆时会自动把每个题名展开成 10 份，变成 80 条，这是正常现象。`seed-course-test.sql` 是独立测试库的夹具，不要灌进主库；`sample_library_data.sql`、`sample_chat_data.sql`、`seed-shop-demo-orders.sql` 都是可选样例，需要时再单独执行。

## SQL 文件不能全部混在一起执行

| 文件 | 执行前提与用途 |
| --- | --- |
| `init.sql` | 基础建库和基础数据，自带 CREATE DATABASE / USE；末尾自带与课程演示库一致的商店、银行演示记录（仅当业务表为空时导入） |
| `migrations/V001` 到 `V007` | 基础库之后，严格按编号执行；V003/V004 不能直接重复执行 |
| `migrations/v101_student_information_batch.sql` | 学籍批量操作回执表 |
| `migrations/v201_ai_tables.sql` | AI 表与知识库数据 |
| `migrations/v301_chat.sql` | 好友关系与文字聊天表，可重复执行；新服务端也会在首次聊天请求时自动建表 |
| `sample_chat_data.sql` | 可选聊天测试申请，先建聊天表；默认张三向李雨桐申请，需对方在客户端同意 |
| `seed/seed-course-demo.sql` | 课程演示数据；统一入口在所有迁移后执行 |
| `migrations/v301_shop_review_and_food_category.sql` | 商店：商品分类新增“食品” + 建商品评价表；init.sql 之后执行，可重复执行 |
| `seed/seed-product-images.sql` | 商品图片种子数据（17 张，约 782 KB）；init.sql 之后随时可执行，只为没有图片的商品补图，可重复执行 |
| `seed/seed-shop-demo-orders.sql` | 商店演示订单（2 笔）与对应银行流水；init.sql 之后随时可执行，可重复执行，会同步账户余额与库存 |
| `seed-course-test.sql` | 独立测试库的测试夹具，不能和演示数据混用，也不能直接重复插入 |
| `sample_library_data.sql` | 图书馆共享测试数据；先执行 init.sql 并启动新服务端完成字段升级，再执行整个文件。非空时跳过基础样例，末尾 A～E 找回测试默认只导入一次 |

所有文件按 UTF-8 导入。迁移与课程种子不自行选库，手工执行前需要 `USE virtual_campus;`。
PowerShell 不支持 cmd 风格的 `<` 输入重定向，优先使用上述入口，避免字符集和选库问题。
不要为运行示例脚本清空当前使用中的图书馆。

例如单独查看连接情况：

```powershell
mysql --host=127.0.0.1 --port=3306 --user=root -p --default-character-set=utf8mb4 --execute="SHOW DATABASES;"
```

## 演示数据与自检

课程演示数据包括 12 门课程、16 个教学班、260 条上课记录、41 条选课记录。
演示账号可使用 `213242789`（学生）、`teacher01`（教师）、`admin3`（课程管理员），初始密码为 `123456`。
已存在账号的密码不会被课程演示脚本重置。

```sql
USE virtual_campus;
SELECT COUNT(*) FROM course;
SELECT COUNT(*) FROM course_offering;
SELECT COUNT(*) FROM course_occurrence;
SELECT COUNT(*) FROM enrollment;
SELECT * FROM _vcampus_sql_history ORDER BY filename;
```

课程时间列按 UTC 存储；转换为北京时间时加 8 小时。

商店与银行同样带演示数据。`init.sql` 末尾的“商店与银行演示业务数据”会在商店业务表和银行流水都为空时导入：12 笔订单（含已支付、已取消、已过期、已退款）、14 条订单明细、1 笔已同意退款、24 条后台操作日志、1 条商品评价、4 条购物车记录、40 条资金流水（商店支付与退款、转账、报销、学费缴纳）、4 笔已通过报销和 1 张已缴清账单，并把账户余额调整到与演示库一致。是否导入先算好并存进 `@seed_demo_shop`、`@seed_demo_bank` 两个变量，已经用过的库不会被动到；记录之间用商品名称、订单号、流水号关联，所以新库的自增编号与演示库不同也能挂上关系，重复执行也不会产生重复数据。

商品图片存在数据库的 `tbl_product_image` 表里，不属于代码仓库。`init.sql` 共建 18 个商品（12 件基础商品 + 便携折叠雨伞2、牙刷、牙膏 + 3 件“食品”）但不带图片，跑一遍 `seed/seed-product-images.sql` 就能给其中 17 个商品补上图（按商品名匹配，不依赖主键；便携折叠雨伞2 本身就没有图片）。另外 `seed/seed-shop-demo-orders.sql` 会再补两笔已支付订单及对应银行流水，只在需要更多订单样例时才跑。图片是原图缩放后的最长边 700 像素 JPEG，只为还没有图片的商品补图，不会覆盖已经上传的图片。

```sql
USE virtual_campus;
SELECT COUNT(*) FROM tbl_product;
SELECT COUNT(*) FROM tbl_shop_order;
SELECT COUNT(*) FROM tbl_shop_refund;
SELECT COUNT(*) FROM tbl_bank_transaction;
SELECT COUNT(*) FROM tbl_product_image;
SELECT user_id, balance FROM tbl_bank_account
WHERE user_id IN ('213242789','213242790','213242792','teacher01','admin');
```

测试夹具 `seed-course-test.sql` 使用独立测试账号及 `course-test-only` 密码，与演示账号不同。
