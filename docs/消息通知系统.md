# 校园消息通知系统

校园消息通知系统是全校业务事件的统一推送与汇聚中心。当系统中发生与用户相关的业务事件（如转账到账、被移出群聊、好友申请通过、学籍教职审核结果等）时，系统自动生成精准的个性化通知，并在系统主页“🔔 消息通知”卡片与“校园消息中心”弹窗中动态呈现，支持未读小红点计数、一键全部已读与跨模块一键直达处理。

---

## 1. 界面入口与交互规则

### ① 主页看板“🔔 消息通知”卡片
- **位置**：系统主页右列上方。学生、教师、管理员各角色均可使用。
- **标头控件**：
  - **未读药丸角标**（`noticeUnreadCountLabel`）：有未读事件通知时显示红色胶囊徽标（如 `3` 或 `99+`）；全部已读后自动隐藏。
  - **全部已读快捷超链接**（`markAllReadLink`）：存在未读通知时出现，点击一键清除未读标记。
  - **消息中心入口**（`openNoticeCenterLink`）：点击打开“校园消息中心”独立弹窗。
- **动态通知流**（`dynamicNoticeContainer`）：
  - 动态展示当前用户最新的 **3~5 条** 未读事件通知；
  - 每一行呈现：彩色分类徽标（如 `[转账]`、`[群聊]`、`[审核]`）、通知正文内容、短时间戳（当天显示 `11:42`，历史显示 `09-17`）与 `查看 >` 链接；
  - **一键直达交互**：鼠标悬停显示手型光标与内容浮窗提示，整行点击或点击“查看 >”后，系统自动将该条通知**标为已读**，并**直接平滑切换到对应的子业务模块**（转账跳银行一卡通、群聊跳聊天、审核跳个人信息）。
- **多业务宏观待办协同**：
  - 卡片同时保留图书馆借阅未还提醒（学生/教师）、商店未支付订单提醒以及管理员审核待办提醒；
  - 仅当宏观待办与事件通知计数全部为 0 时，才呈现清爽的“暂无消息通知”底纹占位面板。

### ② 校园消息中心弹窗 (`NotificationCenterDialog`)
点击主页“消息中心 >”即可打开全量消息管理窗口：
- **分类过滤标签**：支持在 `全部`、`未读`、`财务转账`、`群聊/聊天`、`业务审核` 之间快速筛选；
- **通知详情卡片**：完整展示通知标题、分类徽章、未读红点、正文详情及精确生成时间；
- **快捷操作栏**：
  - 未读项提供“标为已读”按钮；
  - 提供“前往处理 >”按钮，点击后自动标为已读、关闭弹窗并跳转至对应业务页面；
  - 提供“删除”按钮，清理单条通知；
  - 顶部与底部提供“全部已读”、“刷新”和“关闭”功能。

## 3. 数据库表结构与部署

### ① 数据表定义 (`tbl_system_notification`)
通知记录持久化存储于 `tbl_system_notification` 表中：

```sql
CREATE TABLE IF NOT EXISTS tbl_system_notification (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    recipient_uid VARCHAR(32) NOT NULL COMMENT '接收人一卡通号',
    category VARCHAR(32) NOT NULL DEFAULT 'SYSTEM' COMMENT '分类: CHAT, BANK, REVIEW, LIBRARY, SHOP, SYSTEM',
    title VARCHAR(128) NOT NULL COMMENT '通知标题',
    content VARCHAR(512) NOT NULL COMMENT '通知内容',
    link_action VARCHAR(64) DEFAULT NULL COMMENT '跳转目标: CHAT, BANK, STUDENT_STATUS, TEACHER_STATUS, LIBRARY, SHOP',
    is_read TINYINT(1) NOT NULL DEFAULT 0 COMMENT '0-未读, 1-已读',
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY ix_notif_recipient (recipient_uid, is_read, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### ② 部署与初始化
1. **脚本位置**：
   - 数据库增量迁移脚本：`VCampusServer/src/resources/migrations/v302_notification.sql`；
   - 系统全局初始化脚本：`VCampusServer/src/resources/init.sql` Section 9。
2. **免停机自动补表**：
   - 服务端启动或首次收到通知请求/触发业务通知时，`NotificationService.ensureSchema()` 会自动检测并执行幂等建表，无需人工手动刷表，亦不会影响已有业务数据。

## 4. 技术架构与协议设计

### ① 服务端设计 (`VCampusServer`)
- **通信分发**：在 `MessageDispatcher.java` 中注册分发模块 `module = "notification"` 或 `module = "notice"`，交由 `NotificationHandler.java` 处理；
- **接口协议**：
  - `LIST`：支持 `unreadOnly`（布尔值）、`limit`（分页条数，默认 20）、`offset`，返回通知列表及未读总数；
  - `UNREAD_COUNT`：高效查询当前登录用户未读数；
  - `MARK_READ`：根据 `id` 将通知标记为已读（严格校验 `recipient_uid` 本人权限）；
  - `MARK_ALL_READ`：一键将本人所有未读通知标记为已读；
  - `DELETE`：根据 `id` 删除通知记录。
- **业务埋点写入**：
  - `NotificationService.notify(Connection conn, String recipientUid, String category, String title, String content, String linkAction)`：在业务事务内强一致写入通知；
  - `NotificationService.notifyAsync(...)`：在独立线程与连接中异步写入通知，保障主业务流程高可用。
