# 图书馆重复数据修复

2026-09-04 检查发现数据库已有多份字段完全相同、仅自增 ID 不同的记录。客户端通过 `setAll` 替换表格内容，DAO 直接查询单表，重复行来自数据库。重复借阅的图书和时间与演示数据一致，符合重复导入的特征。

本次已备份并清理：借阅 7 条、预约 6 条、书评 4 条、挂失 3 条、罚款 5 条，共 25 条。每组保留最小 ID；所有非 ID 字段均相同才清理，字符串按二进制比较，空值使用 NULL 安全比较。不同借阅时间或状态的记录不会合并。清理后再次检查，五张表的完全重复组均为 0。

本机恢复文件：`backups/library/duplicates-20260904.sql`。文件包含被删除的原始行和 ID，已排除版本控制；仅需要撤销本次清理时才在对应数据库执行。清理在一个事务内完成，先写备份，再删除。

## 维护工具

在项目根目录使用 PowerShell：

```powershell
New-Item -ItemType Directory -Force build-check/library-duplicates | Out-Null
javac --release 25 -encoding UTF-8 -cp 'out/production/VCampusServer;VCampusServer/lib/*' -d build-check/library-duplicates VCampusServer/tools/RepairLibraryDuplicates.java
java -cp 'build-check/library-duplicates;out/production/VCampusServer;VCampusServer/lib/*' RepairLibraryDuplicates
```

默认仅预览，不修改数据库。只有确认这些是错误导入的副本后，才传入 `--apply 新的备份文件路径` 执行清理。工具拒绝覆盖备份，遇到被外键引用的表会停止；不要把该工具接入应用启动流程，也不要对正常业务记录周期性执行去重，尤其是没有事件时间字段的罚款表。

`VCampusServer/src/resources/sample_library_data.sql` 已有非空数据库拒绝导入保护，当前编译输出中的副本也包含此保护。正常启动、重编译和刷新图书馆均不需要导入演示数据。该保护不会自动清理此前已经导入的重复行。
