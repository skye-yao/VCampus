# 信息管理模块说明

信息管理模块用于学生、教师查看和更新个人档案，并为管理员提供信息查询、档案维护、修改申请审核及批量导出功能。本文以当前客户端和服务端实现为准。

## 1. 入口与角色

登录后，从主界面的信息入口进入：学生进入学籍信息页面，教师进入个人信息页面，管理员先选择学生信息或教师信息，也可以在管理页面内切换。

| 角色 | 主要功能 |
| --- | --- |
| 学生 | 查看本人学籍及关联记录，提交个人资料修改申请，撤销待审核申请，维护本人学习经历与家庭关系，导出个人信息 PDF |
| 教师 | 查看本人档案，提交个人资料修改申请，撤销待审核申请，维护本人工作经历与社会关系，导出个人信息 PDF |
| 管理员 | 查询学生和教师档案，直接维护档案资料，审核修改申请，维护学生奖励及资助记录，勾选人员并导出 Excel |

个人档案通过登录账号的 `UID` 关联学生学号或教师工号。账号没有对应档案时，无法加载本人资料；本模块的“维护”主要针对已有档案，不包含独立的学生、教师开户或整份档案删除流程。

## 2. 学生信息管理

### 2.1 信息范围

学生页面包含学籍概览、详细资料和关联记录：

- **个人基本信息**：姓名、性别、民族、政治面貌、证件信息、出生信息、籍贯、户口信息、团员及党员信息、健康状况等。
- **在校信息**：学号、学院、专业、班级、校区、培养方式、学制、辅导员信息等。
- **入学信息**：考生类别、入学日期、入学方式、毕业学校、中学班级及班主任等。
- **联系信息**：电话、手机、邮箱、QQ、微信、校内地址、紧急联系人及联系电话等。
- **关联记录**：主要学习经历、家庭主要关系成员、奖励与资助信息。

展示字段不等于学生可编辑字段。姓名、学号、学院、专业、班级等不在学生个人修改申请的服务端白名单中，需要由管理员维护；其余字段以页面编辑入口及服务端校验为准。

### 2.2 个人资料修改

1. 打开详情，进入编辑状态。
2. 修改允许编辑的字段，补全标有必填提示的信息。
3. 提交申请。系统记录字段名、修改前的值和修改后的值。
4. 等待管理员审核；通过后写入正式学籍，未通过则保留原正式资料。
5. 待审核时可撤销本人申请，再重新编辑、提交。

同一学生已有待审核申请时，不能再次提交新的修改申请。待审核期间页面可以预览修改后的内容，这不代表正式档案已经更新。

### 2.3 学习经历、家庭关系、奖励与资助

- 学生可新增、编辑和删除本人的学习经历及家庭关系。当前页面调用独立增删改接口，成功后直接更新记录，不经过基本资料修改申请的审核流程。
- 学习经历需填写开始年月、结束年月、学校名称和学习阶段，结束时间不能早于开始时间。
- 家庭关系需填写姓名、与本人关系、出生年月、户口所在地、工作单位和联系电话。
- 学习经历最多维护 4 条，PDF 另预留 1 行当前大学经历；家庭成员最多 4 条。客户端提前提示，服务端在事务内锁定所属档案后检查数量，达到上限时不能新增。
- 奖励及资助由管理员新增、编辑和删除，学生查看对应记录。奖励需填写名称、类型和日期；资助需填写名称、类型和日期。

服务端也支持在学生修改申请中表达学习经历、家庭关系的关联变更，供审核处理；这与当前页面使用独立接口直接维护记录的操作路径不同。

## 3. 教师信息管理

### 3.1 信息范围

- **个人基本信息**：姓名、性别、民族、政治面貌、证件信息、出生信息、籍贯、户口信息、党员信息、健康状况等。
- **任职信息**：工号、任职状态、是否在职、校区、学院、部门、职称、职务、学历、入职日期等。
- **联系信息**：电话、手机、邮箱、QQ、微信、办公地址、紧急联系人及联系电话等。
- **经历与关系**：工作经历、主要社会关系成员。

教师可申请修改的字段由服务端白名单限定，其中包括部门、学历、入职日期及个人联系信息等；姓名、工号、学院、职称、职务、任职状态等不属于教师自行申请修改的字段。

### 3.2 修改与维护

教师基本资料遵循“编辑 → 提交申请 → 管理员审核 → 正式生效”的流程，同一教师不能同时保留多份待审核申请。待审核时可以预览提交内容并撤销本人申请。

工作经历与社会关系使用独立接口，由教师维护本人的记录，保存成功后直接生效：

- 工作经历支持新增、编辑、删除，开始时间、工作单位、所在部门和职务必填；结束时间可不填，填写时不能早于开始时间。
- 社会关系支持新增、编辑、删除，姓名、与本人关系、出生年月、户口所在地、工作单位和联系电话必填。
- 教师基本资料中的所在部门、学历和入职日期不能为空。
- 工作经历最多 5 条，社会关系最多 4 条，与单页 PDF 模板对应；数量上限由客户端和服务端共同检查。

## 4. 管理员查询与维护

### 4.1 查询档案

进入“学生信息管理”或“教师信息管理”，通过页面搜索条件筛选人员，在列表中双击记录查看详情。学生列表提供分页浏览，学生和教师列表均支持勾选人员进行 Excel 导出。

### 4.2 直接维护

1. 切换到学生或教师的“信息维护”入口。
2. 选择目标人员并打开详情，进入编辑状态。
3. 修改资料后提交或保存，成功后直接更新正式档案，无需再创建个人修改申请。
4. 刷新详情，确认最终保存结果。

管理员可额外维护学生奖励与资助记录。学习经历、工作经历及家庭／社会关系的独立维护接口按当前登录账号定位所属人员，不能将这些接口当作管理员任意修改他人关联记录的通用接口。

页面进入编辑时会申请档案占用；已有待审核申请时，正常编辑入口会提示先处理申请。学生、教师管理员维护均携带原始档案快照，若资料已被其他操作修改，保存会被拒绝，需要刷新后重新编辑。取消编辑、成功保存和离开页面时释放占用；教师页面在占用失效后退出编辑状态。

## 5. 管理员审核

### 5.1 操作流程

1. 在对应学生或教师管理页面进入“审核信息”。
2. 按状态或搜索条件查找申请，打开审核详情。
3. 核对申请人、提交时间及各修改项的新旧值。
4. 选择通过或未通过；审核意见可不填写，填写时最多 255 个字符，客户端和服务端均检查长度。
5. 操作成功后刷新申请列表和人员档案，确认状态及资料更新结果。

只有待审核申请可以处理。通过时，服务端在同一数据库事务内写入正式资料并更新申请状态；未通过时只更新审核结果，不应用申请内容。申请保存审核人、审核时间和审核意见，已处理申请不能重复审核。

学生和教师审核通过时均核对修改项的旧值与当前正式档案，发生冲突时拒绝覆盖。教师提交申请时也由服务端核对旧值，并保存服务端确认后的值。

### 5.2 申请状态

| 状态值 | 含义 | 后续操作 |
| --- | --- | --- |
| `PENDING` | 待审核 | 管理员通过／未通过，或申请人撤销 |
| `APPROVED` | 已通过 | 修改已写入正式资料，本申请结束 |
| `REJECTED` | 未通过 | 正式资料不变，可重新编辑并提交新申请 |
| `CANCELLED` | 已取消／已撤销 | 正式资料不变，可重新提交新申请 |

学生和教师共用 `StudentChangeStatus` 状态枚举。审核列表包含历史记录，不仅包含待审核申请。

## 6. 导出

| 导出方式 | 操作位置 | 内容与格式 |
| --- | --- | --- |
| 学生个人导出 | 学生详情中的导出按钮 | 学生资料、学习经历、奖励和家庭成员，PDF |
| 教师个人导出 | 教师详情中的导出按钮 | 教师资料、工作经历和社会关系，PDF |
| 管理员批量导出 | 学生／教师信息列表 | 勾选人员的档案字段，Excel `.xlsx` |

导出前需要加载资料；批量导出至少勾选一人。文件通过保存对话框写入本地。个人 PDF 使用页面已加载的正式档案对象，不叠加待审核预览值；审核通过并刷新资料后才会导出新值。

学生奖励按奖励日期从近到远导出最近 4 条（日期相同时按记录编号降序，无日期的记录放最后），不限制奖励维护总数。学生、教师 PDF 都使用固定模板容量；已有超量经历或关系记录不会被删除，导出会提示先整理记录，避免静默遗漏。

## 7. 实现结构

以下路径均相对于仓库根目录。

| 层次 | 主要文件或目录 | 职责 |
| --- | --- | --- |
| 页面与控制器 | `VCampusClient/src/resources/fxml/StudentView.fxml`、`TeacherView.fxml`；`VCampusClient/src/controller/StudentController.java`、`TeacherController.java` | 页面展示、编辑、校验、搜索、审核及导出入口 |
| 客户端服务 | `VCampusClient/src/service/StudentClientService.java`、`TeacherClientService.java`、`LeaseClient.java` | 请求封装、响应回调、编辑与审核占用 |
| 消息处理 | `VCampusServer/src/handler/StudentHandler.java`、`TeacherHandler.java` | 登录会话检查、管理员权限判断、消息分发 |
| 业务服务 | `VCampusServer/src/service/StudentService.java`、`TeacherService.java` | 档案查询、申请提交、字段校验、审核事务 |
| 数据访问 | `VCampusServer/src/dao/Student*DAO.java`、`Teacher*DAO.java` | 档案、申请、变更明细及关联记录读写 |
| 共享模型 | `VCampusCommon/src/entity`、`vo`、`protocol`、`enums` | 实体、概览及审核对象、消息类型与状态 |
| 数据库初始化 | `VCampusServer/src/resources/init.sql` | 表结构及初始化数据 |
| 导出工具 | `VCampusClient/src/util/pdf`、`VCampusClient/src/util/spreadsheet` | PDF 与 Excel 文件生成 |

主要数据表包括：

- 学生档案与关联记录：`tblStudent`、`tblStudentExperience`、`tblStudentFamilyMember`、`tblStudentAward`、`tblStudentAid`。
- 学生申请与明细：`tblStudentChangeRequest`、`tblStudentChangeItem`。
- 教师档案与关联记录：`tblTeacher`、`tblTeacherWorkExperience`、`tblTeacherFamilyMember`。
- 教师申请与明细：`tblTeacherChangeRequest`、`tblTeacherChangeItem`。

个人查询、提交及关联记录维护以服务端会话中的账号为准；管理员列表查询、档案维护和审核由 Handler 检查管理员身份。学生、教师的提交、直接维护、审核及关联记录写入均在 Handler 中校验对应资源锁，并在同一个资源 Guard 内完成校验和业务调用。教师审核先获取申请资源租约；教师关联记录写入取得档案租约后发送请求，完成后释放。

教师管理员维护协议现在需要 `teacher` 和 `original` 两个对象，因此客户端、服务端及 Common 工程应一起重新编译并重启。表结构仍由 `init.sql` 初始化；关联记录写入事务内不再执行建表语句。

## 8. 常见提示与验证

| 提示或现象 | 处理方式 |
| --- | --- |
| 请先登录 | 重新登录后再进入信息页面 |
| 当前用户没有学籍／教师档案 | 检查账号是否已关联对应的学生或教师档案 |
| 已有待审核申请 | 等待审核，或撤销本人的待审核申请后重新提交 |
| 必填字段缺失、日期不合法 | 根据页面标记补全内容，检查起止日期与条件必填日期 |
| 编辑占用失效、档案已变化 | 刷新资料并重新进入编辑，避免继续提交旧页面内容 |
| 申请不存在或已处理 | 刷新审核列表，检查是否已被审核或撤销 |
| 导出按钮不可用 | 等待资料加载，或先勾选需要导出的人员 |

当前回归脚本及运行说明见 [信息管理回归检查](../tests/information/README.md)。脚本覆盖隔离服务端校验、客户端租约与页面清理、FXML 加载以及 PDF 导出边界；不连接真实数据库，不能代替真实 MySQL 写入及并发验收。

手工验收建议使用独立测试数据，依次检查学生／教师的提交、通过、未通过、撤销，管理员直接维护，关联记录增删改，重复提交与重复审核，以及 PDF／Excel 导出。提交后还应分别从申请人和管理员账号查看正式资料与申请状态，确认预览值和正式值的区别。
