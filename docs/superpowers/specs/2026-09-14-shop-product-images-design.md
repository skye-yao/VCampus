# 商店商品图片设计（2026-09-14）

## 目标与前提

- 所有客户端连接同一台正在运行的服务端；服务端连接同一个可共享的 MySQL 数据库。
- 管理员上传或更换商品图片后，其他客户端再次打开商品详情即可看到新图片。
- 换一台电脑运行服务端时，只要它连接原来的 MySQL 数据库，旧图片仍可用；Git 仅同步代码，不能同步运行时新增的数据。
- 现有无图片商品继续可用，详情显示占位图；购物车、订单、银行逻辑不改变。

## 方案选择

采用独立商品图片表保存二进制图片，而不使用服务器本地路径。服务端本地文件需要随服务端迁移额外复制；课程项目图片数量有限，数据库统一备份和迁移更符合本次跨电脑运行要求。客户端不直接连接 MySQL。

## 数据与协议

- `tbl_product_image`：`product_id` 为主键并外键引用 `tbl_product`；保存 `mime_type`、`image_data MEDIUMBLOB`、`updated_at`。图片不放进 `tbl_product`，避免商品列表查询传输二进制数据。
- `init.sql` 增加新表供新数据库初始化；另提供可重复执行的建表迁移语句供现有 `virtual_campus` 使用。不得覆盖现有商品或订单数据。
- `SHOP_PRODUCT_LIST` 保持只返回商品基本信息。
- 现有 `SHOP_PRODUCT_DETAIL` 返回完整商品资料，若有图片则增加 Base64 图片及 MIME 类型；无图时明确返回空值。
- `SHOP_PRODUCT_CREATE` 可附带可选图片。新增商品、保存图片与管理员操作日志在同一 MySQL 事务内提交。
- 增加仅管理员可用的 `SHOP_PRODUCT_IMAGE_SET` 用于更换图片；携带商品 ID、预期版本号与图片数据。更新商品版本、替换图片与记录操作日志在同一事务内完成；版本不符时提示刷新重试。

## 服务端校验与错误处理

- 只接受 JPEG/PNG，限制原始图片不超过 1 MiB；服务端 Base64 解码后用图片解码器确认内容、尺寸及格式，不信任文件名或客户端声明的 MIME 类型。
- 不接受空白、损坏、超大或非图片文件。服务端必须再次校验管理员会话，不能只靠客户端隐藏按钮。
- 上传或数据库写入失败时回滚事务，不留下已创建但缺图的商品，也不生成成功日志。
- 图片通过现有 Socket JSON 请求传输；1 MiB 原图编码后约 1.4 MiB，因此客户端和服务端需明确处理消息大小及上传期间的等待反馈，不能默默超时。

## 客户端界面

- 新增商品弹窗提供可选的选择图片与预览；未选择图片时仍可新增商品。
- 管理员商品维护区显示当前图片或“暂无图片”，提供“更换图片”按钮；成功后刷新预览和操作日志。
- 商品中心及购物车共用同一详情获取流程。详情使用与现有 `style.css` 一致的对话框，展示图片、名称、分类、价格、库存和说明；无图或读取失败时显示占位并允许查看文字资料。
- 图片选择与 Base64 编码不能长时间阻塞 JavaFX 界面；上传时展示进行中状态，错误提示可重试。

## 部署与验证

- 服务端电脑的 `db.properties` 应指向实际共用的 MySQL 地址；当前模板的 `localhost` 仅代表该电脑本机数据库。数据库凭据不写入 Git。
- 验证：无图旧商品、管理员新增含图商品、更换图片、第二客户端立即查看、非管理员上传被拒、损坏或超大图片被拒、并发更换仅一方成功、换服务端电脑但连接同一数据库后图片仍显示。
- 如果将来连 MySQL 数据库也迁走，需要一并迁移数据库备份；只拉取 Git 无法恢复已上传图片。
